# Trae 每日工作入口

## 所有成员上班后的第一条指令

```text
读取飞书“研发交付主表”和 GitHub Project“R&D Delivery”。

只列出与我有关的工作：
1. 我是下一责任人或 Assignee；
2. 我是 Reviewer；
3. 我是 Unblock Owner；
4. 今天或三天内到期；
5. 客户变更影响到我负责的模块。

按以下顺序展示：
Blocked、待我审核、今天到期、In Progress、Ready。

每条显示：
REQ-ID、任务名、当前状态、上游输入、下一动作、截止时间、正式链接。

先只读取和汇总，不要修改数据。
```

## 开始一项工作

```text
我要开始 [REQ-ID / Issue]。

先检查：
- 我是否是当前责任人；
- PRD/TSD/Figma 的状态和版本是否正确；
- 依赖是否解决；
- 验收条件是否可验证；
- 我当前 In Progress 是否已经达到 2 项。

输出执行计划、风险和待确认问题。
我确认后，再更新正式状态。
```

## 完成工作时

```text
检查 [REQ-ID / Issue] 是否满足当前阶段的退出条件。

列出：
- 完成的产物和链接；
- 已运行的检查和真实结果；
- 未完成项；
- 残余风险；
- 下一责任人；
- 建议的下一状态。

如果条件不满足，不要宣称已完成。
我确认后再回写状态并生成通知。
```

## 项目负责人站会前

```text
基于飞书需求主表和 GitHub Project 生成今日摘要。

只列出：
1. Blocked 和解除责任人；
2. 超过 8 工作小时未审核；
3. 两天内到期且不是 On track；
4. 任何人 In Progress 超过 2 项；
5. 新增客户变更；
6. 今天必须做出的决策。

每条必须带责任人、下一动作、时限和原始链接。
不用提交数、代码行数或 AI 用量评价成员。
```
