# 飞书“研发交付主表”建表步骤

## 1. 创建主表

1. 在飞书创建多维表格，命名为“研发交付主表”。
2. 建立“需求主表”数据表。
3. 一行只代表一个父需求，不把每个开发子任务复制进来。
4. 主字段设为 `REQ-ID`，格式为 `REQ-YYYY-NNN`。

## 2. 必建字段

| 字段 | 类型 | 示例/选项 |
|---|---|---|
| REQ-ID | 文本 | REQ-2026-042 |
| 需求名称 | 文本 | 批量导出订单 |
| 客户/提出人 | 文本或人员 | 客户A |
| 父需求DRI | 人员 | PM王敏 |
| 参与角色 | 多选 | PM/设计/TL/Dev/QA/SRE |
| 业务优先级 | 单选 | P0/P1/P2/P3 |
| 业务状态 | 单选 | Intake/Defining/Approved/Delivering/Accepting/Released/Closed/Blocked |
| 研发状态 | 单选 | Not started/Ready/In Progress/In Review/In QA/Ready for Release/Done/Blocked |
| 健康度 | 单选 | On track/At risk/Off track |
| 计划版本 | 文本 | v2.4 |
| 目标日期 | 日期 | 2026-09-30 |
| 当前阻塞 | 长文本 | 原因+解除人+预计时间 |
| 下一动作 | 文本 | TL完成TSD评审 |
| 下一责任人 | 人员 | TL李明 |
| PRD | URL | 飞书文档 |

| 最后更新 | 修改时间 | 自动 |

## 3. 创建视图

- `00-管理驾驶舱`：按健康度和业务状态分组。
- `10-我的工作`：下一责任人为当前用户，且业务状态不是 Closed。
- `20-需求分诊`：业务状态为 Intake 或 Defining。
- `30-风险与阻塞`：健康度不是 On track，或状态为 Blocked。
- `40-待审核`：下一动作包含“评审/审核/验收”。
- `50-客户变更`：变更摘要不为空。
- `60-发布路线`：使用目标日期生成时间视图。

## 4. 今天先录入一条

第一条不要选紧急需求；选择一个能在 5–10 个工作日内完成、包含设计、开发、测试和发布的真实需求。
