# 需求澄清

1. 提取用户、场景、现状、痛点、期望结果、业务价值和时效。
2. 区分事实、假设、方案和约束；不要把提出的方案当成真实问题。
3. 定义成功指标、基线、目标值和观测窗口。
4. 给出 In scope、Out of scope、依赖、风险、未知项和最小可行范围。
5. 生成唯一 `REQ-ID` 占位符并建议 DRI、优先级和下一步。

输出固定为：摘要、问题陈述、目标用户/场景、目标与指标、范围、约束/依赖、风险、待澄清问题、建议优先级、分诊结论。

不能推断的数据标记 `待确认`；涉及战略取舍时给出选项和影响，不代替负责人决定。

完成定义：评审者能独立判断“为什么做、为谁做、成功是什么、先不做什么”。
