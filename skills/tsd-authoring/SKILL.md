# TSD 编写

## 触发条件

- PRD 状态为 Approved，用户要求编写技术方案
- 用户说"写个技术方案"、"出个TSD"、"评估一下怎么实现"
- 技术评审前需要正式文档
- 重大变更需要更新TSD

## 前置条件（不满足则先追问）

1. **PRD 已批准**：状态为 Approved，版本明确
2. **设计已交付**：Figma 冻结版本链接（如涉及前端）
3. **代码上下文可访问**：能读取相关仓库代码和架构文档
4. **TSD模板可用**：使用 [assets/tsd-template.md](assets/tsd-template.md)

如果PRD未批准，先提醒用户走PRD评审，不要直接写TSD。

## 输入要求

### 必需

- 已批准 PRD 的链接和版本号
- Figma 冻结版本链接（如涉及UI）
- 相关代码仓库和目录
- 架构文档和ADR（如有）

### 缺失处理

- 缺少架构文档 → 从代码中推断现状，标注"基于代码推断，待TL确认"
- 缺少设计稿 → 只写后端和数据方案，UI相关标注"待设计交付后补充"
- 缺少非功能需求 → 给出默认建议（如响应时间<500ms），标注"待确认"

## 执行步骤

### 第1步：验证输入并总结现状

1. 确认PRD状态为 Approved，记录版本号
2. 读取相关代码，总结当前实现：
   - 现有模块和职责
   - 相关接口和数据模型
   - 可复用的组件和服务
3. 识别需要改动的模块

### 第2步：方案概览

用一段话描述整体方案：
- 核心思路是什么
- 涉及哪些模块的改动
- 关键技术选型和理由
- 与现有架构的关系

### 第3步：组件与调用流

1. 画出组件关系（文字版时序图或调用链）
2. 说明每个组件的职责
3. 标注同步/异步调用
4. 说明错误传播和重试机制

### 第4步：接口契约

每个新增或修改的接口必须包含：
- **路径和方法**：`POST /api/v1/export-tasks`
- **请求参数**：字段名、类型、必填、说明、示例
- **响应格式**：成功和失败的结构
- **状态码**：200/201/400/401/403/404/409/500等
- **幂等性**：是否幂等，如何保证
- **版本兼容**：老版本客户端如何处理

### 第5步：数据模型与迁移

1. 新增/修改的表和字段
2. 索引设计
3. 数据迁移策略：
   - 优先使用 expand/migrate/contract（先加字段→双写→切读→删旧字段）
   - 说明迁移是否需要停机
   - 迁移脚本和回滚脚本
4. 数据兼容性：旧版本代码能否读写新数据

### 第6步：一致性、并发与幂等

- 关键操作的并发控制（乐观锁/悲观锁/分布式锁）
- 幂等设计：重复请求如何处理
- 最终一致性场景：哪些数据允许短暂不一致，如何收敛
- 事务边界：哪些操作需要事务，隔离级别

### 第7步：安全与隐私

- 权限校验：每个接口需要什么权限
- 数据脱敏：哪些字段需要脱敏存储或展示
- PII处理：涉及个人信息的加密、访问审计
- 输入校验：防止注入、越权、篡改
- 密钥管理：不硬编码，使用配置中心或密钥管理服务

### 第8步：容量与性能

- 预估数据量：日增量、总量、增长率
- 性能目标：响应时间、吞吐量、并发量
- 瓶颈分析：可能的性能瓶颈和优化方案
- 扩容策略：水平/垂直扩容，触发条件

### 第9步：可观测性

- 日志：关键操作日志、错误日志、审计日志
- 指标：业务指标和系统指标
- 链路追踪：关键链路的trace
- 告警：什么情况下告警，通知谁

### 第10步：发布、兼容与回滚

- 发布顺序：先部署什么，后部署什么
- 灰度策略：灰度比例、观察指标、晋级条件
- 兼容性：新旧版本共存时的行为
- 回滚方案：
  - 触发条件（什么情况下回滚）
  - 回滚步骤
  - 数据恢复方案
  - 最大恢复时间（RTO）

### 第11步：测试策略与FR-ID映射

建立 `FR-ID → 组件 → 测试层级` 映射表：

| FR-ID | 涉及组件 | 单元测试 | 集成测试 | E2E测试 | 性能测试 |
|---|---|---|---|---|---|

### 第12步：任务拆分

将方案拆为可独立验收的开发任务：
- 每个任务有明确的输入、输出、验收标准
- 标注依赖关系
- 估算工时（区间）
- 建议Owner（根据组件责任矩阵）

## 输出格式

使用 [assets/tsd-template.md](assets/tsd-template.md) 骨架，正文首部必须包含：

```
状态：Draft
Owner：[TL姓名]
评审人：相关开发、QA
版本：v0.1
关联 PRD：[PRD链接] v1.0
关联 Figma：[冻结版本链接]
关联 REQ-ID：REQ-YYYY-NNN
最后更新：[日期]
```

## 完成定义

- 开发能据此拆任务、编码、测试
- 每个FR-ID都映射到了具体组件和测试
- 接口契约完整，前端/后端可并行开发
- 数据迁移有明确方案和回滚
- 性能目标和容量预估有据可依
- 回滚方案可执行，RTO明确
- 重大技术取舍有ADR或决策记录

## 禁止行为

- 不得凭空设计不存在的组件或服务
- 不得跳过数据迁移和回滚方案
- 不得在未读代码的情况下声称"复用现有组件"
- 不得编造性能数据或容量预估（必须标注假设）
- 不得把PRD中的功能描述直接复制为技术方案
- 不得在未确认的情况下将TSD状态设为Approved
- 不得建议直接删表或不可逆迁移（必须有回滚）

## 与其他Skill的协作

- 上游：`prd-authoring`（PRD）、`figma-handoff`（设计交付）
- 评审：`code-review`（实现后评审）
- 下游：`implementation-planning`（任务拆分）、`test-acceptance`（测试）
- 发布：`release-readiness`（发布检查）

## 示例

### 接口契约示例

```
### 创建导出任务

**POST /api/v1/export-tasks**

**请求体**：
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| filters | object | 是 | 订单筛选条件，同列表页筛选 |
| fields | string[] | 是 | 导出字段列表，受权限控制 |
| format | string | 否 | csv/xlsx，默认csv |

**成功响应 201**：
```json
{ "task_id": "exp_20260914_001", "status": "processing", "estimated_rows": 15000 }
```

**错误响应**：
- 400：筛选条件无效或数据量超限
- 403：无权限导出某些字段
- 409：同时进行中任务超过3个

**幂等**：同一用户+同一筛选条件+5分钟内重复请求，返回已有任务ID。
```
