# TSD 编写

使用 [assets/tsd-template.md](assets/tsd-template.md) 作为默认骨架。

先读取仓库、架构文档和相关 ADR；明确现状，不凭空设计不存在的组件。

按以下结构输出：元数据；目标/非目标；现状；约束；方案概览；组件与调用流；接口契约；数据模型与迁移；一致性/并发/幂等；安全隐私；容量性能；可观测性；发布/兼容/回滚；测试策略；备选方案；风险；任务拆分；未决项。

关键要求：

- 需求 `FR-ID` 必须映射到设计组件与测试层级。
- API/事件/数据变更给出版本兼容和失败语义。
- 数据迁移采用 expand/migrate/contract 或等效安全策略。
- 回滚写明触发阈值、步骤、数据恢复和最大恢复时间。

完成定义：团队可以据此拆任务、编码、测试、部署和回滚；重大取舍已有决策记录。
