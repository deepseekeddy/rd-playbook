# 设计交付检查

## 触发条件

- 设计师完成 Figma 设计稿，要求进行研发交付检查
- 用户说"检查设计稿"、"设计可以交付了吗"、"还原检查"
- PRD已Approved，设计稿已产出，准备进入TSD或开发
- 开发完成后对照设计稿做还原验收
- 需要生成验收截图清单供QA使用

## 前置条件

1. **PRD已Approved**：有版本号和冻结的PRD链接
2. **Figma设计稿可访问**：有Figma文件链接和设计版本号
3. **关联REQ-ID明确**：设计稿对应的需求有REQ-ID

如果PRD尚未Approved，先调用 `prd-review` 完成PRD评审。如果设计稿尚未完成所有页面，只检查已完成的页面，标注未完成项。

## 输入要求

### 必需

- Figma 设计稿链接
- 关联的 PRD 版本和 REQ-ID
- 设计稿版本号或冻结日期

### 缺失处理

- 缺少PRD链接 → 只做视觉一致性和组件检查，不做需求覆盖映射
- 缺少设计版本号 → 以检查日期作为基线，标注"版本号待补"
- 缺少移动端设计稿 → 标注"移动端设计缺失"，只检查桌面端，标注为Major问题
- 缺少交互原型 → 标注"交互原型缺失"，只做静态视觉检查，不做交互流转验证

## 执行步骤

### 第1步：确认设计范围

1. 读取Figma设计稿，列出所有页面/画板（Page/Frame）
2. 对照PRD的FR-ID列表，确认每个FR是否有对应的设计页面
3. 列出已覆盖、未覆盖和超出PRD范围的设计页面
4. 确认设计稿版本号和冻结链接

### 第2步：五态检查（Loading/Empty/Error/Success/Disabled）

对每个关键页面/组件，逐一检查五种状态是否齐全：

| 状态 | 检查要点 | 必需场景 |
|---|---|---|
| **Loading** | 骨架屏/Spinner/进度条样式；加载中文案；是否覆盖所有异步数据区域 | 列表加载、文件上传、消息发送 |
| **Empty** | 无数据时的引导文案和插图；空搜索结果；无历史记录 | 历史会话列表、智能体快捷区、搜索结果 |
| **Error** | 错误提示样式；重试按钮；网络异常提示；权限不足提示 | API加载失败、发送失败、文件超限 |
| **Success** | 操作成功反馈；状态变化后的视觉确认 | 发送成功、上传成功、配置保存 |
| **Disabled** | 禁用态视觉区分（灰化/降低透明度）；禁用态tooltip说明 | 发送按钮（空输入）、提交按钮（加载中） |

对每个页面输出五态覆盖矩阵：

```
| 页面/组件 | Loading | Empty | Error | Success | Disabled |
|---|---|---|---|---|---|
| 工作台首页 | Pass | Pass | Pass | - | Pass |
| 历史会话列表 | Pass | Pass | Pass | - | - |
| 智能体快捷区 | - | Pass | Pass | - | - |
| 对话输入区 | - | - | Pass | Pass | Pass |
```

### 第3步：组件映射

建立 Figma 组件与前端组件库的映射关系：

1. 列出设计中使用的所有Figma组件（Component/Variant）
2. 对照前端组件库（如 Element Plus），标注映射关系
3. 检查是否有需要新建的组件或需要定制变体的已有组件

```
| Figma组件 | 前端组件库映射 | 状态 | 备注 |
|---|---|---|---|
| Button/Primary | el-button type=primary | 已有 | 需定制Lark风格圆角 |
| Button/Disabled | el-button disabled | 已有 | - |
| Sidebar/Item | 自定义组件 | 新建 | 需新建SidebarItem.vue |
| ChatBubble/User | 自定义组件 | 新建 | 需新建ChatBubble.vue |
| Avatar/Small | el-avatar size=32 | 已有 | - |
| Empty/NoAgent | el-empty | 已有 | 需自定义插画 |
```

### 第4步：响应式断点检查

确认设计稿覆盖了所有必要的断点：

1. **桌面端**（大于等于1024px）：主布局、侧边栏展开态、宽屏优化
2. **平板端**（768px至1023px）：侧边栏折叠态、网格列数调整
3. **移动端**（小于等于767px）：汉堡菜单、单列布局、触摸操作优化

对每个断点检查：
- 布局是否适配（是否有溢出、截断、遮挡）
- 交互方式是否切换（鼠标到触摸，hover到tap）
- 文案是否需要精简（桌面端长文案到移动端短文案）
- 导航形式是否切换（顶部菜单到汉堡菜单/底部Tab）

输出响应式覆盖矩阵：

```
| 页面 | 桌面端(>=1024) | 平板端(768~1023) | 移动端(<=767) | 备注 |
|---|---|---|---|---|
| 工作台首页 | Pass | Pass | Pass | 移动端侧边栏改为抽屉 |
| 智能体快捷区 | Pass | Pass | Pass | 移动端改为横向滚动 |
| 对话输入区 | Pass | Pass | Pass | 移动端工具栏收起为展开按钮 |
```

### 第5步：可访问性检查

对照 WCAG AA 标准检查设计稿：

- **对比度**：文字与背景色对比度大于等于4.5:1（正文）/ 3:1（大文字）
- **键盘焦点**：所有交互元素是否有清晰的 focus 样式（outline/border/ring）
- **触摸目标**：移动端按钮/链接最小可点击区域大于等于44x44px
- **alt文本**：所有图片/图标是否有对应的alt文本或aria-label
- **颜色不依赖**：信息传达不仅依赖颜色（如错误状态除红色外还有图标）
- **动画安全**：是否有 prefers-reduced-motion 降级方案

### 第6步：文案与资源检查

1. **文案一致性**：设计稿中的文案与PRD中的描述是否一致
2. **占位符检查**：设计中是否有Lorem ipsum等占位文案未替换
3. **图标许可**：使用的图标是否来自授权图标库或有商用许可
4. **切图规范**：
   - 图标是否为SVG格式（非PNG位图）
   - 图片是否有@1x/@2x/@3x多尺寸
   - 切图命名是否遵循规范（如 icon-search.svg）
5. **设计Token**：颜色、间距、字体是否使用设计变量（非硬编码值）

### 第7步：交互流转验证

对照PRD用户旅程，检查交互原型是否覆盖：

1. 每条用户旅程的路径是否在原型中可走通
2. 异常分支是否有对应的错误页面或提示
3. 页面间跳转是否有明确的转场动画或过渡
4. 表单提交后的成功/失败反馈是否有设计
5. 返回/取消操作是否有明确的交互定义

### 第8步：输出验收截图清单

为QA生成完整的验收截图清单：

```
| 序号 | 页面 | 状态 | 断点 | 截图说明 | 验收标准引用 |
|---|---|---|---|---|---|
| 1 | 工作台首页 | 空白态 | 桌面端 | 首次进入，Hero+空输入区+智能体快捷区 | FR-03 + FR-05 |
| 2 | 工作台首页 | 空白态 | 移动端 | 同上，汉堡菜单折叠态 | FR-03 + FR-05 |
| 3 | 工作台首页 | 输入态 | 桌面端 | 输入框有文字，发送按钮可用 | FR-04 AC1 |
| 4 | 工作台首页 | 加载态 | 桌面端 | 发送消息后，打字机loading | FR-04 |
| 5 | 工作台首页 | 错误态 | 桌面端 | 发送失败，错误提示+重试按钮 | FR-04 异常 |
| 6 | 工作台首页 | 折叠态 | 桌面端 | 侧边栏折叠，主区占满 | FR-01 AC3 |
| 7 | 历史会话列表 | Empty | 桌面端 | 无历史会话，空状态引导 | FR-02 AC1 |
| 8 | 智能体快捷区 | Empty | 桌面端 | 无智能体，引导文案 | FR-05 AC5 |
```

### 第9步：输出检查报告并请求确认

输出完整检查报告，明确标注：
- 设计范围（已覆盖/未覆盖/超出PRD范围的页面）
- 五态覆盖矩阵
- 组件映射表
- 响应式覆盖矩阵
- 可访问性问题
- 缺口和待补充项
- 验收截图清单
- 结论（Pass / Pass with actions / Needs rework）

**Figma是视觉事实源；PRD只记录链接、版本和验收摘要。不得在PRD中复制设计稿内容。**

## 问题分级

| 级别 | 定义 | 处理要求 |
|---|---|---|
| **Blocker** | 关键页面缺失、核心状态未设计、无法开发 | 必须补充，不可进入开发 |
| **Major** | 状态缺失、移动端未覆盖、组件未映射、可访问性不达标 | 应补充，补充后可开发 |
| **Minor** | 文案优化、切图命名规范、Token整理 | 可开发，建议跟进 |

## 完成定义

- 开发无需猜测关键状态（Loading/Empty/Error/Success/Disabled五态齐全）
- QA能从交付物生成视觉与交互用例
- 每个设计页面可追溯到PRD的FR-ID
- 组件映射表覆盖所有Figma组件，标注新建/已有/定制
- 响应式覆盖桌面端和移动端
- 可访问性检查完成，Blocker项为零
- 验收截图清单完整，QA可直接使用

## 禁止行为

- 不得在未查看Figma设计稿的情况下给出"设计没问题"
- 不得跳过五态检查中的任一状态
- 不得把PRD中的功能描述当作设计已交付的证据
- 不得在PRD中复制设计稿内容（PRD只记链接和摘要）
- 不得忽略移动端适配检查
- 不得忽略可访问性检查（WCAG AA是硬性要求）
- 不得把个人审美偏好当成Blocker
- 不得将未冻结的设计版本作为交付基线

## 与其他Skill的协作

- 上游：`prd-review`（PRD评审通过后启动设计交付检查），`prd-authoring`（PRD提供FR-ID和验收标准）
- 下游：`tsd-authoring`（技术方案参考组件映射），`implementation-planning`（任务拆分参考组件新建/定制清单）
- 并行：`code-review`（开发完成后对照验收截图清单做还原检查）

## 检查清单（快速版）

每次检查至少过一遍：
- [ ] PRD版本和REQ-ID已确认
- [ ] 所有FR-ID有对应设计页面
- [ ] 五态覆盖（Loading/Empty/Error/Success/Disabled）
- [ ] 权限差异在设计中体现
- [ ] 边界数据展示规则已设计
- [ ] 移动端断点已覆盖
- [ ] 组件映射完成（新建/已有/定制）
- [ ] 可访问性WCAG AA达标
- [ ] 文案与PRD一致
- [ ] 切图为SVG，图标有许可
- [ ] 设计Token使用变量
- [ ] 交互原型可走通用户旅程
- [ ] 验收截图清单已生成

## 示例

### Blocker 示例

```
### B-1：对话输入区缺少Error态设计
- 位置：ChatInput / 对话输入区
- 问题：设计稿只有正常输入态和空禁用态，缺少文件上传超限和发送失败两个Error态
- 影响：开发无法确定错误提示的样式、位置和文案；QA无法生成错误态测试用例
- 建议：补充两个Error态设计：
  1. 文件超限：输入框上方显示红色提示条"文件大小超限，最大支持10M"
  2. 发送失败：消息气泡显示错误图标+重试按钮
- Owner：设计
```

### Major 示例

```
### M-1：移动端侧边栏缺少抽屉态设计
- 位置：Sidebar / 左侧会话栏
- 问题：桌面端有折叠/展开态设计，但移动端缺少侧边栏抽屉滑入/滑出态
- 影响：开发无法确定移动端侧边栏的交互方式和动画方向
- 建议：补充移动端侧边栏抽屉态设计，包含遮罩层、滑入方向（左到右）、关闭方式（遮罩点击/滑动）
- Owner：设计
```

### Minor 示例

```
### m-1：图标切图包含PNG格式
- 位置：资源文件夹 / icons
- 问题：部分图标同时提供了SVG和PNG格式，PNG切图体积较大且不支持矢量缩放
- 建议：统一使用SVG格式，删除PNG切图以减少包体积
- Owner：设计
```
