# 开发计划

1. 按垂直用户价值切片，避免只按前端/后端形成长串依赖。
2. 每项任务标注 `REQ-ID`、`FR-ID`、Owner、输入、输出、依赖、风险、估算和验收证据。
3. 显式加入测试、数据迁移、埋点、文档、监控、发布和回滚任务。
4. 标出关键路径、可并行项和集成顺序；任务尽量控制在 0.5–2 人日。
5. 给出 Definition of Ready 与 Definition of Done。

输出：里程碑、WBS/Issue 表、依赖图文字版、风险缓冲、集成计划、验收计划。

不要虚构团队容量。估算不确定时给区间与影响因子。
