# PRD 编写

使用 [assets/prd-template.md](assets/prd-template.md) 作为默认骨架。

先读取需求主记录与产品文档集。缺少核心业务口径时列出假设，不编造。

按以下结构输出：文档元数据；背景与问题；目标/非目标；用户与场景；用户旅程；功能需求；业务规则；状态/异常/权限矩阵；非功能需求；数据与埋点；依赖/风险；发布与运营；验收标准；未决项；变更记录。

要求：

- 每项功能使用唯一 `FR-ID`，并关联用户故事与验收标准。
- 验收标准优先采用 Given/When/Then，覆盖正常、空、错误、权限、并发和边界场景。
- 将设计决策留给 Figma/设计规范，将技术实现留给 TSD。
- 指标必须包含定义、公式、基线、目标、数据源和观察周期。

完成定义：PM、设计、TL、QA 可分别据此完成设计、估算、方案和测试，无重大歧义。
