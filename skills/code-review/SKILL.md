# 代码评审

先理解需求/TSD和变更范围，再审查正确性、数据安全、权限、并发、错误处理、兼容、性能、可观测性、测试和可维护性。

问题按 `P0–P3` 排序。每条包含文件/行、可复现情景、实际影响、修复建议；不要把纯风格偏好当缺陷。

验证测试是否覆盖变更风险；若可执行则运行最小相关检查，并如实区分“已运行”“未运行”“无法运行”。

结尾给出：阻塞问题、非阻塞建议、测试证据、残余风险、`Approve/Request changes`。没有证据不得声称测试通过。
